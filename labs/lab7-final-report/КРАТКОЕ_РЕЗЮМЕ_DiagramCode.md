# Краткое резюме проекта DiagramCode

*Отдельный обязательный документ по шаблону `Шаблон_краткого_резюме_проекта_.docx` — ранее не создавался как отдельный файл, только пересказывался внутри общего отчёта.*

## 1. Паспорт проекта и управленческое решение

| Параметр | Значение |
|---|---|
| Название проекта | DiagramCode |
| Инициатор | Ксения Хаджинова, ст. гр. 320604 |
| Суть проекта в 1 предложении | Проект создаёт сервис диаграмм-как-код с AI-генерацией для команд разработки, чтобы решить потерю версионирования и неполный охват нотаций за счёт единого DSL-инструмента с полным набором инженерных нотаций |
| Запрашиваемое решение | Ограниченный старт (пилот на сегменте ПВТ Беларуси) |
| Граница первого старта | Беларусь (ПВТ) + русскоязычное СНГ, команды разработки ПО |

## 2. Идея, рыночная возможность и достаточность рынка

| Блок вывода | Краткая запись |
|---|---|
| Идея | Отсутствие версионирования у визуальных редакторов и неполный охват нотаций/AI у существующих DSL-инструментов проявляется у команд разработки, документирующих архитектуру в git |
| Спрос | Google Trends показывает рост индекса PlantUML на ≈231% за 3 года 3 месяца и Breakout-запрос `text to diagram ai` |
| Границы рынка | Беларусь + СНГ, команды разработки, DSL-инструменты с AI |
| Размер рынка | SOM ≈$9 600/год достаточен для проверки в 1-й год; SAM ≈$21 600–28 800/год; TAM (потолок) ≈$479 000/год |
| Барьеры входа и выхода | Главные барьеры — доверие (репутация с нуля против PlantUML) и растущие затраты на AI-провайдера; управляемы через специализацию и квоту запросов |

**Итог этапа**: проект имеет основание для старта — подтверждены проблема, спрос (с региональной привязкой), понятная конкурентная позиция, управляемые барьеры и возможность проверить ценностное предложение в первом релизе.

## 3. Конкурентная среда и незакрытая проблема

| Вывод | Формулировка |
|---|---|
| Уровень конкуренции | Прямые: PlantUML, Mermaid, MermaidChart, Eraser.io. Близкие: D2, draw.io. Косвенный: Lucidchart. Заменитель: Visio |
| Рыночный стандарт | Текстовый DSL + браузерный рендер + интеграция с GitHub — обязательный минимум |
| Конкурентные преимущества | Полный охват инженерных нотаций (UML+ERD+IDEF+BPMN+сети Петри) в одном продукте — ни у кого из конкурентов нет |
| Главная проблема клиента | Клиент не может версионировать диаграммы как код и одновременно получать AI-генерацию и полный охват нотаций без переключения между несколькими инструментами |

## 4. Ценностное предложение, цифровой товар и монетизация

| Элемент | Содержание |
|---|---|
| Целевой сегмент | Команды разработки ПО и техписатели ПВТ Беларуси/СНГ |
| Опорная проблема | Потеря версионирования либо неполный охват нотаций+AI |
| Ценностное предложение | Для команд разработки, хранящих документацию в git, которые сталкиваются с потерей версионирования диаграмм, DiagramCode обеспечивает мгновенную версионируемую инженерную диаграмму из DSL или текста через AI с полным охватом нотаций, лучше чем PlantUML/Mermaid (нет AI) и Eraser.io (нет полного охвата) |
| Цифровой товар | IDE-оболочка (редактор + канвас) с AI-модалкой, версионированием и реестром нотаций |
| Единица монетизации | Подписка по местам, $8/участник/мес ≈ $480/год, AI-квота на тариф |
| Потенциал удержания | История версий, накопленный DSL-код команды — растущие издержки переключения со временем |

## 5. Бизнес-модель по Канвас (сокращённо)

| Блок | Содержание |
|---|---|
| Сегменты | ПВТ Беларусь → СНГ → глобальные разработчики |
| Ценность | Полный охват нотаций + AI + версионирование в одном продукте |
| Каналы | Органика (поиск, GitHub), сообщества разработчиков |
| Отношения | Самообслуживание (Free) + поддержка (платные тарифы) |
| Доходы | $8/участник/мес × количество мест в команде |
| Ресурсы и процессы | Реестр нотаций, AIProvider, DSL-грамматика; разработка по волнам |
| Партнёры и затраты | LLM-провайдер, GitHub, хостинг; переменные затраты — AI API |

**Итог этапа**: бизнес-модель собрана — ценностное предложение, товар, монетизация, канал и первый релиз поддерживают одну и ту же задачу.

| Блок | Показатель | Плановое значение | Что означает |
|---|---|---|---|

| Риски | Рост затрат на LLM API быстрее платящей базы | Высокий | Контролируется AI-квотой (20 запросов/день) |

## 8. Итоговая формулировка решения

**Пилот**: рекомендуется ограниченный пилот в границах ПВТ Беларуси/СНГ, поскольку ценностное предложение перспективно, но требует проверки готовности реальных команд платить именно за охват нотаций, а не за AI как таковой. Объём пилота: первый релиз в минимальном составе; критерий продолжения — конверсия Free → платный тариф выше нуля в течение первых 3 месяцев.

## 9. Краткий вывод

Проект DiagramCode целесообразно рассматривать как SaaS-инструмент диаграмм-как-код с AI-генерацией для команд разработки ПВТ Беларуси/СНГ. Его ценность основана на решении проблемы разрыва между версионированием и AI+полнотой охвата нотаций, подтверждённой реальными данными Google Trends (рост категории, региональное совпадение) и анализом конкурентов (незакрытая ниша). Первый релиз должен быть ограничен функциями DSL-редактор + рендер + версии + оплата, которые сохраняют ключевое ценностное обещание и позволяют проверить спрос, оплату и удержание. Инвестиционное решение: **пилот** при условии контроля затрат на AI-провайдера квотой.
