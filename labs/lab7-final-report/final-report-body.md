## 1 РЕЗЮМЕ ПРОЕКТА

Проект **DiagramCode** — сервис визуального моделирования диаграмм через собственный текстовый DSL (UML, ERD, IDEF0/1X/3, DFD, BPMN, сети Петри) с git-подобным версионированием, AI-генерацией по тексту/изображению и совместным редактированием.

Спрос подтверждается устойчивым многолетним ростом интереса к категории «диаграмма как код» и резким структурным сдвигом спроса в сторону AI-генерации диаграмм по тексту (раздел 3). Рынок старта — компании Парка высоких технологий Беларуси (более 1000 компаний) и русскоязычное IT-сообщество СНГ, достаточный для проверки бизнес-модели при базовом сценарии выручки $22 000-29 000/год (раздел 4). Конкурентная среда насыщенная (PlantUML, Mermaid, Eraser.io, D2), но ни один конкурент не закрывает полный охват инженерных нотаций в одном продукте — это ниша DiagramCode (разделы 5-7). Ценностное предложение — мгновенная, версионируемая диаграмма из DSL-кода или текста через AI (раздел 8), реализуемая по бизнес-модели с подпиской по местам и AI-квотой на тариф (раздел 9). Первый релиз — DSL-редактор + рендер + сохранение версий + нотация `erd.crows_foot.logical` + аутентификация (раздел 12).

**Рекомендация**: стартовать проект в границах русскоязычного IT-сообщества (ПВТ Беларусь + СНГ) с первым релизом в минимальном составе, поскольку подтверждены растущий спрос, достаточный для проверки размер рынка и незакрытый конкурентами пробел в охвате нотаций.

## 2 ИДЕЯ И ИСХОДНАЯ ГИПОТЕЗА

| Элемент | Значение |
|---|---|
| Проблема | Диаграммы либо теряют историю версий при хранении в визуальных редакторах (draw.io, Visio, Lucidchart), либо не имеют AI-генерации, полного охвата нотаций и совместного редактирования при хранении в существующих текстовых DSL-инструментах (PlantUML, Mermaid) |
| Клиент | Команды разработки ПО и техписатели, уже хранящие документацию в git-репозитории |
| Текущее решение | Визуальные GUI-редакторы (бинарный/XML-формат, не версионируется построчно) либо PlantUML/Mermaid (версионируются, но без AI и совместного редактирования) |
| Предлагаемое решение | Текстовый DSL + git-подобное версионирование + AI-генерация по тексту/изображению + IDE-оболочка + совместное редактирование, с полным охватом инженерных нотаций |
| Единица монетизации | Подписка по местам с AI-квотой на тариф |
| Гипотеза старта | Минимальный первый релиз (одна нотация ERD + рендер + сохранение + auth) достаточен для проверки готовности целевого сегмента платить за AI-квоту сверх бесплатного лимита |

## 3 АРГУМЕНТАЦИЯ СПРОСА: GOOGLE TRENDS И ЯНДЕКС ВОРДСТАТ

Полный текст с данными — [лабораторная работа №1](../lab1-demand/lab1-demand.md).

Реальные данные Google Trends (снято 17.09.2026, Worldwide, 5 лет): категория-лидер `PlantUML` — устойчивый рост среднего индекса интереса от ~15-20 (2021) до пиков 90-100 (середина 2026). Фраза `text to diagram` показывает структурный сдвиг: стабильный уровень 10-20 в 2021-2024 годах сменяется устойчивым подъёмом до 50-100 с июля-августа 2025 года — держится больше года, то есть это не сезонность и не разовый всплеск, а новый уровень тренда. Это прямое подтверждение спроса на AI-генерацию диаграммы по тексту — ключевую функцию DiagramCode.

Яндекс Вордстат недоступен без личной авторизации в Яндекс ID (актуальное ограничение сервиса на 2026 год) — раздел не заполнен данными по русскоязычному сегменту напрямую; инструкция по самостоятельному снятию — в лабораторной работе №1, раздел 10.

**Вывод**: поисковый спрос на категорию растёт, причём быстрее всего растёт именно AI-ориентированный сегмент внутри неё — это и есть рыночное основание идеи DiagramCode.

## 4 ГРАНИЦЫ И РАЗМЕР РЫНКА

Полный текст с расчётами — [лабораторная работа №2-3](../lab2-3-market-size/lab2-3-market-size.md).

Границы рынка: продукт — DSL-инструменты для диаграмм с AI-генерацией; клиент — команды разработки ПО; география старта — русскоязычное IT-сообщество (Беларусь + СНГ); канал — поиск, GitHub, сообщества разработчиков.

Реальные опорные данные: более 1000 компаний зарегистрировано в Парке высоких технологий Беларуси, свыше 40% — с иностранным капиталом (доля IT в ВВП Беларуси — 6,1% на I кв. 2025, источник: opencompanyinbelarus.com); ближайший прямой аналог `plantuml.com` получает Россию как топ-страну трафика (9,07%), что подтверждает цифровую активность именно в целевом географическом сегменте; коммерческий продукт `mermaidchart.com` почти не представлен в этом регионе (топ-страны — Вьетнам, Индонезия, США) — конкурентный пробел.

Расчёт «сверху вниз» и «снизу вверх» дают согласованный диапазон **$15 000-29 000/год** для стартового сегмента ПВТ Беларуси в осторожном/базовом сценарии, с потенциалом кратного роста при расширении на СНГ (оптимистичный сценарий — свыше $150 000/год).

**Вывод**: рынок старта достаточен для проверки бизнес-модели минимальным первым релизом.

## 5 КОНКУРЕНТНАЯ СРЕДА И УРОВНИ КОНКУРЕНЦИИ

Полный текст — [лабораторная работа №5](../lab5-competitors/lab5-competitors.md).

Прямые конкуренты (по взвешенной шкале методики): PlantUML, Mermaid (открытое ядро), MermaidChart (коммерческий), Eraser.io, D2. Близкий конкурент: D2. Заменители: draw.io/Lucidchart/Visio, ручное рисование, отказ от диаграмм.

Рыночный стандарт цифрового товара: текстовый DSL + браузерный рендер без установки + интеграция с GitHub-экосистемой, к которому AI-генерация быстро добавляется как новый обязательный элемент (уже ядро продающего предложения у Eraser.io). **Ни один прямой конкурент не закрывает весь набор инженерных нотаций (UML + ERD + IDEF0/1X/3 + DFD + BPMN + сети Петри) в одном продукте** — это конкурентный пробел для DiagramCode.

## 6 БАРЬЕРЫ ВХОДА И ВЫХОДА

Полный текст — [лабораторная работа №4](../lab4-porter/lab4-porter.md).

Средневзвешенная оценка пяти сил Портера — **4,0 из 5 (высокое конкурентное давление)**, driven главным образом высокой силой покупателей (лёгкость сравнения с бесплатными PlantUML/Mermaid) и очень высокой угрозой заменителей, а не числом прямых конкурентов. **Вывод**: вход на рынок возможен только при чёткой специализации (полный охват нотаций) — не через прямую конкуренцию по фиче-листу с Eraser.io.

## 7 ПРОБЛЕМЫ ПОЛЬЗОВАТЕЛЕЙ И РЫНОЧНЫЕ ПРОБЕЛЫ

Ключевая проблема (см. разделы 2, 5): команды либо теряют версионирование диаграмм (визуальные редакторы), либо не получают AI-генерацию и полный охват нотаций (существующие DSL-инструменты). Проблема имеет функциональный (нет единого инструмента для всех нотаций) и организационный (сложно поддерживать актуальность диаграмм вручную) характер.
