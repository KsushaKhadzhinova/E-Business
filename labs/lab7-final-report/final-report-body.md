## 1 РЕЗЮМЕ ПРОЕКТА

Проект **DiagramCode** — сервис визуального моделирования диаграмм через собственный текстовый DSL (UML, ERD, IDEF0/1X/3, DFD, BPMN, сети Петри) с git-подобным версионированием, AI-генерацией по тексту/изображению и совместным редактированием.

Спрос подтверждается устойчивым многолетним ростом интереса к категории «диаграмма как код» (индекс PlantUML вырос ≈231% за 3 года 3 месяца, см. раздел 3) и резким структурным сдвигом спроса в сторону AI-генерации диаграмм по тексту, включая growing-запрос `text to diagram ai` со статусом Breakout. Рынок старта — компании Парка высоких технологий Беларуси (более 1000 компаний) и русскоязычное IT-сообщество СНГ; допущение подкреплено реальными данными — Беларусь входит в топ-5 стран мира по интересу к PlantUML (раздел 3). Оценка рынка даёт TAM (потолок) $479 399/год, SAM (обслуживаемый рынок) $28 800/год, SOM (достижимо в 1-й год) ≈$9 600/год (раздел 4) — **все три цифры остаются допущениями, требующими проверки**, а не подтверждённым фактом. Конкурентная среда насыщенная (PlantUML, Mermaid, Eraser.io, D2), но ни один конкурент не закрывает полный охват инженерных нотаций в одном продукте — это ниша DiagramCode (разделы 5-7). Ценностное предложение — мгновенная, версионируемая диаграмма из DSL-кода или текста через AI (раздел 8), реализуемая по бизнес-модели с подпиской по местам ($8/участник/мес ≈ $480/год) и AI-квотой на тариф (раздел 9). Первый релиз — DSL-редактор + рендер + сохранение версий + нотация `erd.crows_foot.logical` + аутентификация + экран тарифов/оплаты (раздел 12).

**Рекомендация**: стартовать проект в границах русскоязычного IT-сообщества (ПВТ Беларусь + СНГ) с первым релизом в минимальном составе, с сужением позиционирования до нишевой специализации (полный охват нотаций + AI), поскольку подтверждены растущий спрос, достаточный для проверки размер рынка (SOM-сценарий) и незакрытый конкурентами пробел в охвате нотаций.

## 5 КОНКУРЕНТНАЯ СРЕДА И УРОВНИ КОНКУРЕНЦИИ

Полный текст — [лабораторная работа №5](../lab5-competitors/lab5-competitors.md).

По реальной 8-критериальной формуле методики (веса: задача 0,22 / сегмент 0,18 / продукт 0,18 / заменяемость 0,18 / каналы 0,10 / цена 0,08 / результат 0,04 / видимость 0,02, шкала 0-4, пороги 80-100/65-79/50-64/35-49/20-34/0-19): **прямые конкуренты** — PlantUML (90,0), Mermaid open-source (90,0), MermaidChart (83,5), Eraser.io (93,0, самый близкий аналог); **близкие конкуренты** — D2 (79,5), draw.io (67,5); **косвенный** — Lucidchart (63,5); **заменитель** — Microsoft Visio (49,5); **потенциальный конкурент** — универсальные AI-ассистенты, используемые вручную для генерации кода диаграмм (26,5).

Модель Левитта показывает: у прямых конкурентов «расширенный товар» — это глубина экосистемы (плагины/интеграции), не охват нотаций. Модель Кано классифицирует полный охват нотаций как **привлекательную (excitement)** характеристику — не ожидается рынком, но радует и дифференцирует.

Рыночный стандарт цифрового товара (6-классовая типология): текстовый DSL и браузерный рендер — **обязательные практики** (100% прямых конкурентов); интеграция с GitHub — **распространённая**; AI-генерация — **усиливающая практика**, растёт быстро; **полный охват инженерных нотаций — редкая практика (0 из 4 прямых конкурентов)** — это конкурентный пробел для DiagramCode.

## 7 ПРОБЛЕМЫ ПОЛЬЗОВАТЕЛЕЙ И РЫНОЧНЫЕ ПРОБЕЛЫ

Ключевая проблема (см. разделы 2, 5): команды либо теряют версионирование диаграмм (визуальные редакторы), либо не получают AI-генерацию и полный охват нотаций (существующие DSL-инструменты). Проблема имеет функциональный (нет единого инструмента для всех нотаций) и организационный (сложно поддерживать актуальность диаграмм вручную) характер.

### Приложение 4 — Заключение

По результатам анализа рекомендуется **ограниченный старт** проекта DiagramCode в границах русскоязычного IT-сообщества (Беларусь + СНГ). Спрос подтверждён устойчивым ростом категории и реальным региональным совпадением (Беларусь #5 в мире по PlantUML). Рынок в выбранных границах оценивается как минимально достаточный для проверки (SOM ≈$9 600/год) — не с запасом. Опорная проблема (отсутствие инструмента с полным охватом нотаций+AI+версионированием) подтверждена анализом конкурентов. Ценностное предложение — полный охват инженерных нотаций с AI-генерацией и git-подобным версионированием. Первый релиз должен включать DSL-редактор, рендер, сохранение версий, аутентификацию и экран оплаты — и не должен включать совместное редактирование, OAuth и полный охват нотаций (это Волны 2–4). Переход к следующему релизу целесообразен при подтверждении готовности хотя бы части ПВТ-команд платить за AI-квоту сверх бесплатного лимита. Ключевые риски — рост затрат на LLM API быстрее платящей базы (контроль — квота) и низкая узнаваемость бренда против многолетнего PlantUML (контроль — специализация на охвате нотаций, а не прямая конкуренция по фиче-листу).
